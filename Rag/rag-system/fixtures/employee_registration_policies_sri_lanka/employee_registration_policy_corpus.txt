# EMP-REG-001 — Employee User Registration Governance Policy

**Scope:** ERP employee registration for Sri Lanka only  
**Status:** Synthetic research policy for RAG validation

## Rules
1. Only an authorized HR Administrator or System Administrator may create a new employee user.
2. Managers may request registration but may not create the user unless they also hold an approved administrator role.
3. Self-registration is not permitted.
4. The creator must be authenticated and recorded in the audit trail.
5. All mandatory fields must pass validation before creation.
6. Foreign-country employee registrations are outside this workflow.
7. The employee record is created only when the final validation result is ALLOW.

## Mandatory fields
Gender, Birth Date, Phone, Location, Email, First Name, Last Name, Language, Time Zone.

## Optional field
Middle Name.

EMP-REG-002_Name_Validation.md
================================================================================
# EMP-REG-002 — Employee Name Validation Policy

## Rules
1. First Name and Last Name are mandatory.
2. Middle Name is optional.
3. Names must not contain digits.
4. Unicode alphabetic characters are permitted, including Sinhala, Tamil, and Latin scripts.
5. Spaces, hyphens, apostrophes, and periods used for initials are allowed.
6. Leading/trailing spaces must be removed.
7. Repeated internal spaces should be normalized.
8. Each name field must be 100 characters or fewer.
9. Placeholder values such as `test`, `unknown`, or `n/a` are not accepted for mandatory name fields.

EMP-REG-003_Gender_and_Birth_Date.md
================================================================================
# EMP-REG-003 — Gender and Birth Date Validation Policy

## Gender
Accepted values:
- Female
- Male
- Other
- Prefer not to say

Values outside the accepted list are blocked.

## Birth Date
1. Birth Date is mandatory.
2. It must be a valid calendar date.
3. Store as `YYYY-MM-DD`.
4. It must not be in the future.
5. It must not be today's date.
6. Missing or invalid dates are blocked.
7. Clearly implausible dates are escalated for HR review.

EMP-REG-004_Sri_Lanka_Phone_Validation.md
================================================================================
# EMP-REG-004 — Sri Lanka Phone Validation Policy

## Rules
1. Phone is mandatory.
2. Only Sri Lankan numbers are accepted.
3. The international country code must be `+94`.
4. A local number beginning with `0` may be normalized to `+94`.
5. After normalization the value must be `+94` followed by 9 digits.
6. Spaces, hyphens, and brackets may be removed during normalization.
7. Alphabetic characters are not allowed.
8. Non-Sri Lankan country codes are blocked.
9. The normalized phone number must be unique among active employee users.

## Examples
- `0771234567` -> `+94771234567` -> ALLOW
- `+94771234567` -> ALLOW
- `+919876543210` -> BLOCK

EMP-REG-005_Sri_Lanka_Location_Validation.md
================================================================================
# EMP-REG-005 — Sri Lanka Location Validation Policy

## Rules
1. Location is mandatory.
2. The employee location must be within Sri Lanka.
3. Accepted country identifiers are `Sri Lanka`, `LK`, and `LKA`.
4. Any location explicitly identifying another country is blocked.
5. If province or district is provided, it must be a valid Sri Lankan province or district.
6. Ambiguous locations that cannot be verified as Sri Lankan are escalated.
7. Country must not be inferred from the phone number alone.
8. The system must never silently replace a foreign country with Sri Lanka.

EMP-REG-006_Email_Validation.md
================================================================================
# EMP-REG-006 — Employee Email Validation Policy

## Rules
1. Email is mandatory.
2. It must use valid `local-part@domain` structure.
3. Spaces are not permitted.
4. The domain must contain at least one dot.
5. Normalize to lowercase for duplicate checking.
6. Email must be unique among active employee users.
7. Malformed addresses are blocked.
8. If the company maintains an approved corporate-domain list, the entered domain must match that configured list.
9. The model must not invent the company's email domain.

EMP-REG-007_Language_and_Time_Zone.md
================================================================================
# EMP-REG-007 — Language and Time Zone Validation Policy

## Language
Supported values:
- English
- Sinhala
- Tamil

Codes may be normalized:
- `en` -> English
- `si` -> Sinhala
- `ta` -> Tamil

Other language values are blocked unless the supported-language configuration is updated.

## Time Zone
1. Time Zone is mandatory.
2. The canonical value is `Asia/Colombo`.
3. `UTC+05:30` may be normalized to `Asia/Colombo` only if the application supports that mapping.
4. Foreign time zones are blocked.

EMP-REG-008_Duplicate_User_Detection.md
================================================================================
# EMP-REG-008 — Duplicate Employee User Detection Policy

## Rules
1. Duplicate checking occurs before final creation.
2. Email must be unique.
3. Normalized phone must be unique.
4. Same normalized name plus the same Birth Date is a potential duplicate and must be escalated.
5. Same name plus matching phone or email must be blocked unless this is an approved correction of an existing record.
6. Capitalization and spacing differences must not bypass duplicate checks.

## Decisions
- Exact active email match -> BLOCK
- Exact normalized phone match -> BLOCK
- Same name + same Birth Date -> ESCALATE

EMP-REG-009_Field_Completeness_and_Normalization.md
================================================================================
# EMP-REG-009 — Field Completeness and Normalization Policy

## Mandatory fields
Gender, Birth Date, Phone, Location, Email, First Name, Last Name, Language, Time Zone.

Middle Name is optional.

## Normalization
1. Trim leading/trailing spaces.
2. Normalize repeated spaces.
3. Lowercase email for comparison.
4. Normalize phone to `+94` format.
5. Normalize Time Zone to `Asia/Colombo`.
6. Normalize accepted Language codes to canonical language names.
7. Do not silently change invalid Birth Date, Gender, Name, or Location values.
8. Missing mandatory fields are blocked.

EMP-REG-010_Validation_Decision_and_Audit.md
================================================================================
# EMP-REG-010 — Validation Decision and Audit Policy

## ALLOW
Use ALLOW only when:
- creator is authorized;
- all mandatory fields are present;
- every field passes its validation policy;
- no duplicate conflict exists;
- location is Sri Lanka;
- phone is Sri Lankan;
- time zone is accepted.

## BLOCK
Use BLOCK when:
- creator is unauthorized;
- a mandatory field is missing;
- a field is malformed;
- country is not Sri Lanka;
- phone country code is not `+94`;
- time zone is not accepted;
- language is unsupported;
- an exact duplicate email or phone exists.

## ESCALATE
Use ESCALATE when:
- location is ambiguous;
- a potential duplicate needs human confirmation;
- a plausible value cannot be verified automatically.

## Audit
Record requester ID, timestamp, submitted employee reference, validation result, failed policy IDs, and any manual override.

# EMP-REG-011 — Combined Employee Registration Validation Flow

## Validation order
1. Requester authorization -> EMP-REG-001
